# Contributing

Everyone is welcome to test, report bugs, improve documentation, and submit pull requests.

## Reports

Include your Windows version, app/source revision, steps to reproduce, expected result, actual result, and whether analysis reported a limit. Prefer a minimal program you built yourself or an openly redistributable sample. Do not publish secrets, personal data, proprietary binaries, or active malware in issues.

## Changes

Keep each pull request focused. Explain the problem, the change, and how you verified it. Add meaningful regression tests for analysis correctness or crashes. Preserve truthful partial-coverage reporting. Avoid running input binaries as part of static analysis.

Run the native tests described in README.md. Desktop changes should also be exercised in the app; the existing smoke tests need the upstream development dependencies and local fixtures described in the component READMEs.

## Contribution license

By submitting an original contribution for inclusion, you agree to license it under AGPL-3.0-only. Only submit material you have the right to contribute. Identify any third-party material and preserve its notices. No copyright assignment is required. Contributions do not grant a separate proprietary licensing exception.

## Collaboration

Discuss technical ideas respectfully. Useful bug reports, accessibility feedback, documentation, and test results are as welcome as code. The project is an early preview; the roadmap records planned features rather than promises that they already exist.
